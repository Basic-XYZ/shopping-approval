# 安全与上线门禁

## 已实现

- 入口校验微信注入的 OPENID 与允许的 AppID；未配置时拒绝服务。
- 身份 ID 由服务端计算，不信任客户端用户或审批人字段。
- 所有读写限定当前有效双人关系；每次绑定使用新关系 ID。
- 绑定、解绑和审批使用事务；审批携带版本号，防止过期请求覆盖。
- 一次性128位随机邀请码，服务端仅存哈希；生成限流、24小时有效。
- 金额在服务端严格解析为整数分，审批原因、长度和链接协议校验。
- 不向响应回显运行环境、密钥或 SDK 原始错误，不下载用户提供的商品链接。
- 数据库客户端读写关闭的配置清单已提供，但尚未应用到云环境。

## 未完成的上线门禁

- 真实 AppID、环境关联、云函数权限和数据库规则尚未验证。
- 真机双人流程、云端事务冲突、网络断开重试与性能配额尚未验证。
- 昵称/申请文本尚未接入微信内容安全审核；正式分发前补齐。
- 隐私保护指引、账号注销、历史数据保留/清除政策待产品确定。
- 邀请码持有者可申请绑定，第一版只有受邀者确认；正式开放可考虑增加发起者二次确认。
- 使用 offset 分页，列表并发新增时可能出现跨页重复；下拉刷新重置分页。

## 依赖审计（2026-09-05）

微信 SDK 固定为 `wx-server-sdk@4.0.2`。升级后去除了旧版依赖中的 critical 告警，但 `npm audit` 仍报告6项（5 high、1 moderate），涉及上游 `@cloudbase/node-sdk`、`@cloudbase/database`、`axios`、`lodash.set`、`lodash.unset` 依赖链。

未执行自动强制降级 SDK，也未使用未经集成验证的传递依赖替换掩盖告警。正式部署前需要评估可达性、上游修复版本或经验证的兼容替换。**测试通过不等于依赖安全审计通过。**

复查命令：在 `cloudfunctions/shoppingApi` 执行 `npm audit`。锁文件固定本次依赖，后续升级需重跑 SDK 契约和云端测试。
